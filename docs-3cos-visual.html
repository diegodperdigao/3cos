1.2. Tipografia

Duas famílias — Montserrat para display (títulos, wordmark), Inter para body/UI.

--fd: 'Montserrat', sans-serif;   /* display: títulos, wordmarks, labels */

1.4. Shadows e efeitos

Poucos shadows explícitos — o app depende mais de borders sutis + glow colorido (via box-shadow spread) do que sombras densas.

/* Glow accent (usado em botões theme, cards ativos) */
box-shadow: 0 0 0 3px var(--theme-glow);

/* Card lift no hover */
box-shadow: 0 8px 24px rgba(0, 0, 0, 0.3);

/* Glass border (transparente + backdrop-filter) */
border: 1px solid var(--glass-border);
backdrop-filter: blur(12px);

1.5. Iconografia

Lucide (lucide.dev) via CDN. Todos os ícones no HTML como <i data-lucide="X"></i> — a função lucide.createIcons() substitui por SVG inline após cada render.

  • Tamanho padrão: 15-16px (top bar), 24px (module cards), 18px (buttons)
  • Stroke default: 2px (Lucide padrão)
  • Stroke fino em cards de módulo: 1.7px (via .hub-app-icon svg { stroke-width: 1.7 })
  • Cor sempre via stroke: currentColor ou custom (--app-stroke)

2. Screenshots das telas principais

Capturas em viewport 1440×900 · tema dark · usuário admin com todos os módulos. Os ícones dos módulos aparecem como quadrados placeholders porque o Lucide (CDN) foi bloqueado no ambiente de captura — no navegador real aparecem os ícones específicos de cada função.

2.1. Hub (tela inicial)

Fluxo pós-login. Contém top bar, greeting hero, faixa de widgets customizáveis e grid de módulos. Container: #hub em position: fixed; inset: 0; z-index: 190.

Hub padrão · usuário admin · 4 widgets defaults (Resultado, Fila de pagamentos, Minhas tarefas, Notificações) · 10 módulos no grid

2.2. Copilot — tela de boas-vindas

Drawer lateral direito (~440px) sobreposto ao hub. Fundo do hub é escurecido via #copilot-overlay (backdrop). Botão + no header inicia nova conversa, hamburger abre histórico.

Copilot aberto sem mensagens · ícone Gemini brand-pink + 4 suggestion chips clicáveis

2.3. Copilot — conversa em andamento

Bubbles diferentes para user (sem avatar, alinhado à direita) e assistant (com avatar Gemini pink, alinhado à esquerda). Suporta markdown básico (**bold**, *italic*, `code`, listas - item).

Conversa exemplo — pergunta do usuário + resposta formatada em markdown com lista e negrito

2.4. Widget picker modal

Modal disparado pelo botão "Personalizar widgets" (canto superior do grid de módulos). Cada row é um <label class="hwp-row"> com checkbox nativo + ícone + nome + descrição. Widgets ativos ganham border e background rosa via .hwp-row:has(:checked).

Modal de personalização · 4 widgets ativos destacados em rosa · 2 inativos em cinza · botão Salvar em cor de marca

2.5. Action Center (drawer de notificações)

Drawer lateral direito acionado pelo botão sino no top bar. Diferente do Copilot: #action-center tem largura menor (~360px) e é para notificações do sistema.

Central de Ações aberta · lista de alertas do sistema em drawer lateral

2.6. Light mode

Ativado por document.documentElement.setAttribute('data-theme', 'light'). Sobrescreve --bg, --text, borders e as cores semânticas (theme vira #db2777, verde mais escuro, etc). Toggle no botão sun/moon do top bar.

Hub no tema light · mesma estrutura, paleta invertida · usa --bg: #f8fafc + --text: #0f172a

JS

function toast(text, type = 's'){  // 's', 'w', 'e'
  const el = document.createElement('div');
  el.className = 'toast ' + type;
  el.textContent = text;
  document.getElementById('toasts').appendChild(el);
  setTimeout(() => el.remove(), 3500);
}

4. Sistema de temas e editions

O sistema tem 2 dimensões: mode (dark/light) e edition (default/mono/bento/meridian/neonflow/glass). Aplicadas via 2 atributos no <html>:

<html data-theme="dark" data-edition="">         <!-- default dark -->
<html data-theme="light" data-edition="">        <!-- default light -->
<html data-theme="dark" data-edition="glass">    <!-- Liquid Glass dark -->
<html data-theme="light" data-edition="mono">    <!-- Mono light -->

4.1. Storage e THEME_MAP

Salvo em STATE.settings.theme como string composta (edition-mode). Decodificado em applyAppTheme():

const THEME_MAP = {
  'default-dark':   { edition: '',         theme: 'dark'  },
  'default-light':  { edition: '',         theme: 'light' },
  'mono-dark':      { edition: 'mono',     theme: 'dark'  },
  'mono-light':     { edition: 'mono',     theme: 'light' },
  'bento-dark':     { edition: 'bento',    theme: 'dark'  },
  'bento-light':    { edition: 'bento',    theme: 'light' },
  'meridian-dark':  { edition: 'meridian', theme: 'dark'  },
  'meridian-light': { edition: 'meridian', theme: 'light' },
  'neonflow-dark':  { edition: 'neonflow', theme: 'dark'  },
  'neonflow-light': { edition: 'neonflow', theme: 'light' },
  'glass-dark':     { edition: 'glass',    theme: 'dark'  },
  'glass-light':    { edition: 'glass',    theme: 'light' },
};

window.applyAppTheme = () => {
  const key = STATE.settings?.theme || 'default-dark';
  const pair = THEME_MAP[key] || THEME_MAP['default-dark'];
  const root = document.documentElement;
  root.setAttribute('data-theme', pair.theme);
  if (pair.edition && STATE.user) root.setAttribute('data-edition', pair.edition);
  else root.removeAttribute('data-edition');
};
Regra importante: data-edition só é aplicado quando STATE.user existe. A tela de lock/login sempre fica no default para consistência visual.

4.2. Como um novo tema é definido no CSS

Cada tema sobrescreve as mesmas CSS variables. Os componentes nunca dependem do tema — eles consomem apenas variables.

/* Default dark é o :root */
:root {
  --theme: #ec4899;
  --bg: #060810;
  --text: #f1f5f9;
  /* ... */
}

/* Light override — só as variables que mudam */
[data-theme="light"] {
  --bg: #f8fafc;
  --text: #0f172a;
  --theme: #db2777;
  /* ... */
}

/* Mono edition — deixa tudo preto/branco */
[data-edition="mono"] {
  --theme: #ffffff;
  --pink: #ffffff; --blue: #ffffff;
  --fd: 'Space Mono', monospace;
}
[data-edition="mono"][data-theme="light"] {
  --theme: #000000;
  --bg: #ffffff;
}

/* Glass edition — habilita backdrop-filter em componentes */
[data-edition="glass"] .hub-widget,
[data-edition="glass"] .modal,
[data-edition="glass"] .drawer{
  background: rgba(255,255,255,0.06);
  backdrop-filter: blur(20px) saturate(180%);
  border: 1px solid rgba(255,255,255,0.12);
}
[data-edition="glass"] body::before {
  content:''; position:fixed; inset:0;
  background:
    radial-gradient(60% 60% at 20% 30%, rgba(236,72,153,0.35), transparent 70%),
    radial-gradient(50% 50% at 80% 70%, rgba(168,85,247,0.30), transparent 70%);
  z-index:-1;
}

4.3. Toggle simples (só dark ⇄ light)

Botão do sun/moon no top bar. Não muda a edition, só o mode.

window.toggleTheme = () => {
  const cur = document.documentElement.getAttribute('data-theme') || 'dark';
  const next = cur === 'dark' ? 'light' : 'dark';
  document.documentElement.setAttribute('data-theme', next);
  // Sincroniza com settings.theme
  const curKey = STATE.settings.theme || 'default-dark';
  const [edition] = curKey.split('-');
  STATE.settings.theme = `${edition}-${next}`;
  saveToLocal();
  // Atualiza o ícone
  const icon = document.getElementById('theme-icon');
  if (icon) icon.setAttribute('data-lucide', next === 'dark' ? 'moon' : 'sun');
  if (window.lucide) lucide.createIcons();
};

4.5. Boas práticas para novos temas

  • Nunca hardcode cor em componente — sempre var(--nome). Se precisar de uma cor nova, adicione ao :root.
  • Light mode = simetria — para cada var no :root, defina o equivalente em [data-theme="light"]. Não deixa rgba(255,255,255,X) aparecer em light (fica invisível).
  • Editions são aditivas — sobrescrevem só o que muda. Se um edition não define uma variável, herda do :root.
  • Ícone do tema — atualize o data-lucide do #theme-icon sempre que trocar (sun ↔ moon) e re-rode lucide.createIcons().
  • Persistência — sempre salve em STATE.settings.theme + saveToLocal() para sobreviver reload.

5. Como reusar em outro projeto

Guia prático para portar o design system inteiro — ou pedaços dele — para outro projeto. As instruções assumem stack sem build system (mesmo que o original), mas funcionam em qualquer framework se você extrair só o CSS.

5.1. Portabilidade mínima (starter kit)

Se quiser apenas a base visual (paleta + tipografia + botões + cards), você precisa de:

  1. Fonts no <head>: 
    <link href="https://fonts.googleapis.com/css2?family=Inter:wght@400;500;600;700;800;900&family=Montserrat:wght@600;700;800;900&display=swap" rel="stylesheet">
  2. Lucide antes do </body>: 
    <script src="https://unpkg.com/lucide@latest"></script>
<script>lucide.createIcons();</script>
  3. CSS foundation (paleta + reset + tipografia base) — copiar as Seções 1 deste doc.
  4. Componentes que precisar — Seção 3 tem cada um isolado com HTML+CSS+demo.

5.2. Portabilidade completa (visual system inteiro)

Para trazer todo o sistema, incluindo hub + widgets + copilot + temas:

  1. Arquivos a copiar:
    • css/styles.css — todo o CSS (paleta, componentes, temas)
    • js/app.js — funções globais (showHub, buildHubCards, openMod, goBack, helpers)
    • js/widgets.js — sistema de widgets
    • js/copilot.js — chat IA (opcional)
    • js/settings.js — apenas as funções applyAppTheme, toggleTheme, THEME_MAP
    • Trecho HTML do #hub (linhas 143-212 do index.html original)
  2. Adaptar:
    • Array MODS[] em app.js — módulos do novo projeto
    • Wordmark: substituir 3C<em>OS</em> pelo nome do novo produto
    • Logo: trocar src das imagens imgbb pelas do novo projeto
    • Prefixos do localStorage: 3cos_* → seuprojeto_*
    • Cores dos módulos no MODS[] — adaptar ao branding
  3. Não copiar (dependências do domínio 3C):
    • System prompt do Copilot (linguagem sobre iGaming)
    • MODS[] com IDs 3C-específicos (payments, affiliates, etc)
    • Renderers de widgets que leem STATE.payments, STATE.affiliates, etc — reescrever para dados do novo domínio

5.3. Ordem recomendada de porte

  1. Foundations (paleta + tipografia + espaçamento) — a base sem a qual nada funciona.
  2. Um botão + um card — validar que as CSS vars estão OK.
  3. Top bar do hub (logo + search + icon buttons + user chip).
  4. Grid de módulos com MODS[] adaptado.
  5. Sistema de temas (dark ⇄ light no mínimo).
  6. Modal + toast — infraestrutura para modais de configuração.
  7. Widgets — depois que hub estiver estável.
  8. Copilot — por último, requer backend Vercel + Gemini key.
